# snakego · 选手程序接口（SDK / 协议）

> 本文件由 `scripts/gen_gamepacks.py` 从 A 的 `games/snakego/evaluator/arena.py` 的协议
> 说明生成。协议是**公开**信息（不是任何人的策略），可安全提供给 Goal 阅读。

## 你要交付什么

一个可运行的选手包，入口是 `main.py`：

- 进程启动后进入循环：读一帧输入 → 计算 → 写一帧输出；
- 角色：['P0', 'P1']；同一份代码要能在任一角色下运行；
- 只能用标准库与包内自带模块；**不联网**、**不写文件**（沙箱会拒绝）；
- 任何格式错误 / 超时 / 崩溃都会被判负（对战器返回 `game_error`），
  所以**第 0 版的首要目标是协议完全正确**，强度其次。

## 对局传输协议（来自 A 的对战器）

SnakeGo 官方 stdio 判题协议对局执行内核（游戏资产），属仓库 A。

SnakeGo 沿用 Saiblo 长度前缀 stdio 判题协议：后端(main.py)与判题器之间的每个包为

    [length: 4 bytes big-endian signed][target: 4 bytes big-endian signed][body]

- ``target >= 0``：直接发给该编号选手的**二进制**消息（配置/道具/操作回显/结束）。
- ``target == -1``：控制 JSON。轮次配置 ``{state:0,time,length}``；轮次消息
  ``{state,listen,player,content}``（向 ``player`` 广播 ``content``、监听 ``listen``
  中的选手）；终局 ``{state:-1,end_info,end_state}``。

选手侧（``games/snakego/players/pool/`` 里的官方 SDK）线协议：
- 读 stdin 原始字节：配置 5 字节、道具 ``0x10``+``count:2``+7*count、操作单字节 1..6、
  终局 ``0x11``+6 字节。
- 写 stdout：``[len:4][op:1]``（op ∈ 1..6）。

判题器把选手输出帧的 **body**（去掉 4 字节长度前缀）作为 ``content`` 回传给后端，
后端 ``on_received_operation`` 再 ``int.from_bytes`` 解析成操作码——故本 arena
**不重新封帧**（这是与 antwar2 的关键差异）。

本模块自包含轻量数据结构，不依赖任何框架层。

## 自检建议

1. 先写一个只做合法动作的最小版本，确认能跑完整局（拿到 `complete` 而不是 `game_error`）；
2. 再逐步加入策略；每次改动都用一局诊断对局验证；
3. 读 `gamepack/replay_skill.md` 学会从回放定位自己的失误。
