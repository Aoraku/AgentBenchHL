# aquawar · 选手程序接口（SDK / 协议）

> 本文件由 `scripts/gen_gamepacks.py` 从 A 的 `games/aquawar/evaluator/arena.py` 的协议
> 说明生成。协议是**公开**信息（不是任何人的策略），可安全提供给 Goal 阅读。

## 你要交付什么

一个可运行的选手包，入口是 `main.py`：

- 进程启动后进入循环：读一帧输入 → 计算 → 写一帧输出；
- 角色：['P0', 'P1']；同一份代码要能在任一角色下运行；
- 只能用标准库与包内自带模块；**不联网**、**不写文件**（沙箱会拒绝）；
- 任何格式错误 / 超时 / 崩溃都会被判负（对战器返回 `game_error`），
  所以**第 0 版的首要目标是协议完全正确**，强度其次。

## 对局传输协议（来自 A 的对战器）

AquaWar (25th) length-prefixed match transport and role-correct results.

AquaWar 的对局执行内核（游戏资产），属仓库 A。用 4 字节大端长度前缀 + 4 字节
object_id 的 stdio 协议驱动官方 C++ 后端与两名 C++ 选手完成一局（三局两胜），
产出角色感知的 ``MatchResult`` 与回放。

与 antwar2 的协议差异：
- init 消息不含随机种子（AquaWar 先手固定=0、确定性）；
- 终局标志是后端广播 ``{"state": -1, "end_info": "{...}"}``（state==-1），
  而非 antwar2 的 ``end_state`` 键；
- 胜负从 replay JSON 末尾 state 的 ``score`` 判定（score>0 → P0 胜，<0 → P1 胜，
  0 → 平局），``rounds`` 为已进行的小局数（最多 3）。

## 自检建议

1. 先写一个只做合法动作的最小版本，确认能跑完整局（拿到 `complete` 而不是 `game_error`）；
2. 再逐步加入策略；每次改动都用一局诊断对局验证；
3. 读 `gamepack/replay_skill.md` 学会从回放定位自己的失误。
