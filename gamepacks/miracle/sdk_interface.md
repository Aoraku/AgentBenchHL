# miracle · 选手程序接口（SDK / 协议）

> 说明生成。协议是**公开**信息（不是任何人的策略），可安全提供给 Goal 阅读。

## 你要交付什么

一个可运行的选手包，入口是 `main.py`：

- 进程启动后进入循环：读一帧输入 → 计算 → 写一帧输出；
- 角色：['P0', 'P1']；同一份代码要能在任一角色下运行；
- 只能用标准库与包内自带模块；**不联网**、**不写文件**（沙箱会拒绝）；
- 任何格式错误 / 超时 / 崩溃都会被判负（对战器返回 `game_error`），
  所以**第 0 版的首要目标是协议完全正确**，强度其次。

## 对局传输协议（来自 A 的对战器）

Miracle 的对局传输层：Saiblo judge 协议驱动 + 角色感知结果。

Miracle 的对局执行内核（游戏资产）属仓库 A。本模块用 Saiblo judge 协议在 Python
后端与两名选手之间转发消息，完成一局对战，产出角色感知的 ``MatchResult`` 与回放。

协议要点（与 `replay_format.md` / 后端 `main.py` 一致）：
- 后端 stdout 帧 = ``[4B big-endian length][4B big-endian goal][json body]``；本游戏
  所有帧 goal 恒为 -1，路由由 body 内的 ``player``/``listen``/``content`` 决定。
- body 形态：
  * ``{"state":0,"time","length"}`` —— send_init 计时通知，judge 忽略并读下一帧；
  * ``{"state":s,"listen":[p],"player":[p],"content":["<内层长度前缀json>"]}`` ——
    需把 content[0] 的字节原样写给选手 p 的 stdin，然后读回选手一帧回复；
  * ``{"state":-1,"end_info":"<json {"0":s0,"1":s1}>"}`` —— 终局。
- judge -> 后端 stdin 帧 = ``[4B big-endian length][json {"player":p,"content":"<opt json>"}]``。
- 选手 -> judge 帧 = ``[4B big-endian length][opt json]``（选手 send_opt）。
- judge -> 选手 stdin：直接写后端给的 content 字节（其内已含选手侧长度前缀）。

本模块自包含轻量数据结构，不依赖框架层。

## 自检建议

3. 读 `gamepack/replay_skill.md` 学会从回放定位自己的失误。
