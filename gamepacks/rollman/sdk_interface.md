# rollman · 选手程序接口（SDK / 协议）

> 本文件由 `scripts/gen_gamepacks.py` 从 A 的 `games/rollman/evaluator/arena.py` 的协议
> 说明生成。协议是**公开**信息（不是任何人的策略），可安全提供给 Goal 阅读。

## 你要交付什么

一个可运行的选手包，入口是 `main.py`：

- 进程启动后进入循环：读一帧输入 → 计算 → 写一帧输出；
- 角色：['rollman', 'ghost']；同一份代码要能在任一角色下运行；
- 只能用标准库与包内自带模块；**不联网**、**不写文件**（沙箱会拒绝）；
- 任何格式错误 / 超时 / 崩溃都会被判负（对战器返回 `game_error`），
  所以**第 0 版的首要目标是协议完全正确**，强度其次。

## 对局传输协议（来自 A 的对战器）

Rollman 官方 stdio 判题协议对局执行内核（游戏资产），属仓库 A。

Rollman 沿用 Saiblo 长度前缀 stdio 判题协议（`logic/utils.py`）：

- 后端→判题器：``[length: 4B unsigned][target: 4B signed][body]``
  （``struct.pack(">Ii", ...)``）。``target == -1`` 为控制 JSON；``target ∈ {0,1}``
  为直接发给该选手的字节流。
- 判题器→后端（后端 ``receive_from_judger``）：只读 ``[length: 4B unsigned][body]``
  （**无 target**）。

控制 JSON：
- 回合配置 ``{state:0, time, length}``（判题器计时用）。
- 回合消息 ``{state, listen:[i], player:[...], content:[...]}``：``listen`` 指定要监听的
  选手；``player``/``content`` 指定要转发文本给哪些选手（座位号、reset、step 结果都走这里
  或走 target 直发）。
- 终局 ``{state:-1, end_info, end_state}``。

选手侧（官方 SDK，`games/rollman/players/pool/`）：读 stdin **文本行**（``input()``，
判题器原样转发字节流），写 stdout **帧** ``[len:4 unsigned][json]``，其中 json 为
``{"role": 0|1, "action": "d" | "d1 d2 d3"}``。

Rollman 是**非对称严格锁步**博弈，但本 arena 采用与 SnakeGo 相同的**异步双向泵**实现，
它对锁步是安全超集：后端帧 ``target>=0`` 立即转发给选手；控制消息的 ``player/content``
文本转发给对应选手；选手一旦产出输出帧就立刻作为 ``{player,content}`` 回传后端。

本模块自包含，不依赖任何框架层。

## 自检建议

1. 先写一个只做合法动作的最小版本，确认能跑完整局（拿到 `complete` 而不是 `game_error`）；
2. 再逐步加入策略；每次改动都用一局诊断对局验证；
3. 读 `gamepack/replay_skill.md` 学会从回放定位自己的失误。

## 候选脚手架与填空契约（自动生成）

`candidate_interface` = `AI.decide`。候选包里已经放好**官方 SDK**（与人类选手当年拿到的逐字节相同），协议层不需要你实现。

**你只需要写 `ai.py`，在其中定义 `class AI`。**

这是**非对称游戏**，两个座位玩的不是同一个游戏，官方也发了两套 SDK。候选包里按角色轨分成 `rollman_sdk/`、`ghost_sdk/`，入口 `main.py` 会读环境变量 `AGENTBENCH_ROLE`（取值 `rollman` / `ghost`）自动选择对应那套，并把角色写到 `self.role` 上。

**同一份 `ai.py` 要能应付两个角色**——一次 run 里你的代码会被派去打每个角色。用 `self.role` 分支即可。
