# AntWar2 Goal Charter

从零构造一个确定性、可审计、可解释的 AntWar2 程序策略，并在未弱化的
官方人类选手池上持续研究，直到冻结认证矩阵中的全部有效比赛获胜。

## 研究方法

1. 先阅读规则、公开 SDK、原子决策空间和回放阅读指南。
2. 在看任何人类回放前，根据规则编写第一版完整策略 `v000`。
3. 与 Framework 指定的未击破人类进行官方比赛，双方均保持完整运行资源。
4. 把公开回放的数字状态和操作翻译为自然语言事实，定位关键状态窗口。
5. 每轮探索默认从同一 parent 产出 `k=4` 个策略候选。每个候选可以是一套协同修改，
   需要写明公开回放依据、失败机制、策略包、预期回放变化和主要风险；不是只能修改一个
   动作或一个阈值。
6. 四个候选在同一诊断对局条件下各打一局，比较四份公开回放。只有胜出或明显改善的
   候选才追加确认局；稳定击败 rank01 使用四个固定 seed 的角色均衡检查。
7. 保存支持、否定、混合、未触发和工程失败经验；不得丢弃失败知识。
8. Champion 保留最佳版本；Frontier 允许暂时失败，并可从任意 Archive 版本继续。
9. 按榜单从排名最低的未击破可运行人类向更强人类推进，并持续回归已击破者。

## 策略边界

允许条件规则、状态机、路径规划、启发式评分、资源预算、确定性搜索和角色专用
逻辑。允许代码增长、策略包和局部修补。反事实与消融用于理解和选择，不是提出策略包
的前置条件。禁止读取人类源代码、按对手身份/seed/replay ID
分支、访问隐藏引擎状态、导入参考策略，以及用无因果区别的参数网格搜索代替回放
分析。

所有科研状态变更必须通过 `abhl` CLI 完成。候选代码只能写入 CLI 返回的活动工作
区。比赛、版本封存、晋升、回滚、认证和指标以 Framework 事件为事实来源。
