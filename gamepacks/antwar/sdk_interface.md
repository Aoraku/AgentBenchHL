# antwar · 选手程序接口（SDK / 协议）

> 本文件由 `scripts/gen_gamepacks.py` 从 A 的 `games/antwar/evaluator/arena.py` 的协议
> 说明生成。协议是**公开**信息（不是任何人的策略），可安全提供给 Goal 阅读。

## 你要交付什么

一个可运行的选手包，入口是 `main.py`：

- 进程启动后进入循环：读一帧输入 → 计算 → 写一帧输出；
- 角色：['P0', 'P1']；同一份代码要能在任一角色下运行；
- 只能用标准库与包内自带模块；**不联网**、**不写文件**（沙箱会拒绝）；
- 任何格式错误 / 超时 / 崩溃都会被判负（对战器返回 `game_error`），
  所以**第 0 版的首要目标是协议完全正确**，强度其次。

## 对局传输协议（来自 A 的对战器）

AntWar (27th) length-prefixed match transport and role-correct results.

AntWar 的对局执行内核（游戏资产），属仓库 A。用 4 字节大端长度前缀 + 4 字节
object_id 的 stdio 协议驱动官方 C++ 后端与两名 C++ 选手完成一局，产出角色感知的
``MatchResult`` 与回放。

AntWar（27 届）协议要点（与 aquawar 同构，差异见下）：
- init 时后端主动发一帧 ``{"state":1,"listen":[],"player":[0,1],"content":[oj0,oj1]}``
  把 ``"{id} {seed}
"`` 推给两名选手（无需回复）；
- 每回合 ``listen(p)`` 先发一个 config 帧 ``{"state":0,"time":..,"length":..}``
  （无 listen/player）需忽略，再发 listen 帧要选手 p 回复；
- 选手操作被后端以 ``object=1-p`` 直接转发给对手（object∈{0,1} 帧直接搬运）；
- 每回合末发 ``{"state":round,"listen":[],"player":[0,1],"content":[oj0,oj1]}``
  推 OJ 文本状态给两选手（无需回复）；
- 终局后端广播 ``{"state":-1,"end_info":"{"0":s0,"1":s1}","end_state":"[...]"}``，
  ``end_info`` 中 s0=1 → P0 胜，s1=1 → P1 胜。
- 后端 config 可含 ``random_seed``；本对战器**固定 seed** 保证可复现。

## 自检建议

1. 先写一个只做合法动作的最小版本，确认能跑完整局（拿到 `complete` 而不是 `game_error`）；
2. 再逐步加入策略；每次改动都用一局诊断对局验证；
3. 读 `gamepack/replay_skill.md` 学会从回放定位自己的失误。
