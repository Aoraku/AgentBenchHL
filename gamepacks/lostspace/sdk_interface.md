## 你要交付什么

一个可运行的选手包，入口是 `main.py`：

- 进程启动后进入循环：读一帧输入 → 计算 → 写一帧输出；
- 角色：['P0', 'P1', 'P2', 'P3']；同一份代码要能在任一角色下运行；
- 只能用标准库与包内自带模块；**不联网**、**不写文件**（沙箱会拒绝）；
- 任何格式错误 / 超时 / 崩溃都会被判负（对战器返回 `game_error`），
  所以**第 0 版的首要目标是协议完全正确**，强度其次。

## 对局传输协议（来自 A 的对战器）

LostSpace 的对局传输层：Saiblo judge 协议（N 人异步双向泵）+ 名次结果。

LostSpace 是四人对抗对战。与双人"发一条等一条"不同，本游戏后端在单个玩家回合内
连续多次 ``recieve_data``，而广播/见证消息只是单向通知。因此裁判采用**纯异步双向
泵**模型（与真实 Saiblo judge 一致）：

- 后端 stdout 帧 = ``[4B big-endian length][4B big-endian goal][json body]``（goal 恒 -1）；
  body 为 ``{"state","listen":[..],"player":[p...],"content":[str...]}`` 或
  ``{"state":0,...}``（计时）或 ``{"state":-1,"end_info":"..."}``（终局）。
- 裁判把 ``content[i]`` 的字节原样写给玩家 ``player[i]`` 的 stdin（其内已含选手侧
  长度前缀），**不阻塞等待**。
- 任一玩家 stdout 帧 = ``[4B big-endian length][opt json]``；裁判把它包成
  ``{"player":p,"content":"<opt json>"}`` 写给后端 stdin。
- 读到 ``state == -1`` 即终局，据 ``end_info`` 的名次分裁决。

## 自检建议

1. 先写一个只做合法动作的最小版本，确认能跑完整局（拿到 `complete` 而不是 `game_error`）；
2. 再逐步加入策略；每次改动都用一局诊断对局验证；
3. 读 `gamepack/replay_skill.md` 学会从回放定位自己的失误。
